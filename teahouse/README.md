# teahouse

一个本地单用户的角色扮演前端。核心三件事：**角色卡**、**世界书**、**提示词栈**。

设计目标是**完全兼容 SillyTavern 的世界书文件**——网上能用的 JSON 世界书，这里都能用。
世界书文件以原始字节存盘，编辑通过字段映射写回原文，所以未知字段永远不会被丢掉。

零运行时依赖，零构建步骤。

> 设计决策与理由见 [DESIGN.md](DESIGN.md)：架构、兼容层、提示词栈语义、测试体系都在那里。

## 快速开始

```bash
node --version        # 需要 >= 23（原生跑 TypeScript）
npm start             # 默认 http://127.0.0.1:8787
```

打开页面后：

1. 点右上角「设置」，填接口地址、API Key、模型名，保存
   - 任何 OpenAI 兼容端点都行：DeepSeek、OpenAI、Ollama、LM Studio、vLLM、OpenRouter…
   - 例如 DeepSeek：`https://api.deepseek.com/v1` + `deepseek-chat`
   - 设置分五类（通用设置 / 外观 / 模型 / 角色扮演 / 世界书），左栏切换，方向键也能换页；
     有未保存改动的分类上会有一个小圆点
2. 左下「导入角色卡」选一张 PNG 或 JSON 卡片（角色卡内嵌的世界书会自动生效）
3. 左下「导入世界书」选一个 JSON，勾选即挂到当前会话
4. 中间开始聊

## 三个面板

- **左**：角色卡 / 世界书（勾选挂载）/ 会话
- **中**：对话，支持流式输出、重新生成（swipe 变体）、从任意一条重开
- **右**：提示词栈（点击方块可开关，真实生效并记住）、**世界书命中**（顶部下拉是本会话的检索模式；下面写哪条命中、命中了哪个键、为什么）、请求预览（真实的 messages）

右上的「世界书命中」是排障主力：世界书不生效时，能直接看到是本轮没扫到、
被预算挤掉、还是被 cooldown 挡住了。

## 编辑

**世界书条目**：点世界书名字打开编辑器。可以新增、复制、删除、逐字段修改条目，
也能改这本书自己的「扫描深度 / token 预算 / 递归扫描」。表单由 `GET /api/worlds/fields`
的字段元数据生成——那份元数据同时是服务端校验补丁的依据，所以加字段不会两边不同步。

编辑**按原格式写回**：数组形态的书（CharacterBook）仍然写 `keys` / `insertion_order` /
`enabled`，Risu 仍然写逗号连接的 `key` 与 `insertorder`。原文档里我们看不懂的字段一律原样保留，
连副本都带上。外格式没有对应位置、但用户确实改过的字段会存到 `extensions.tavern` 下，默认值不写。

**角色卡**：点列表项的 `⋯` →「编辑卡片」，可以改**名字、作者、版本、标签、描述、性格、场景、
首条消息、备用问候、示例对话、系统提示词、历史后指令、创作者备注**。表单的字段表
（`web/js/character-fields.js`）与服务端接受补丁的字段表（`EDITABLE_CARD_FIELDS`）是同一份，
`test:web` 会交叉校验，所以不会出现「界面能填、保存被丢掉」这种事。写入走的是导入器那条**无损**路径：
PNG 卡仍是 PNG 卡，看不懂的字段照旧原样保留。

同一菜单还能改显示名、改 id（目录名，会一并迁移它的会话）、导出卡片 JSON、**导出卡片 PNG**、删除
（有会话时默认拒绝，界面会问你是否连会话一起删）。PNG 导出给的就是那张卡自己的载体（内嵌着当前数据）；
本来就是 JSON 载体的卡会在菜单里把这一项置灰并说明原因。

**开场白**：新建会话时会自动把卡片的**首条消息**作为第一条消息落下（角色先开口，而不是空对话等你先说）。
卡片有备用问候时，菜单里多一项「新会话（换一个问候…）」，可以挑一个来开局；`POST /api/chats`
接受 `greeting: <索引>`（`0` = 首条消息，`-1` = 不要问候），问候文本由服务端从卡片里取，
调用方塞不进任意文本。

**世界书可以导出成酒馆原生格式**（列表项的 `⋯` 菜单），这样从别的工具拿来的书能直接给酒馆用。

## 交互

**每条消息**：悬停出现工具条，右键打开同一份菜单。可以复制正文、**内联编辑**、
重试这条回复、从这里重开、只删除这一条。编辑保存后会重新拉取装配预览，
所以 token 与命中面板会跟着正文一起更新。

带 swipe 变体的回复编辑的是**当前激活的那个变体**，其它候选不会被静默丢掉。
「只删除这一条」会把后续消息重新挂到它前面一条上，其余对话完整保留；
「从这里重开」会先确认将删除多少条。

**分叉**：消息菜单里的「从这里分叉出新会话」会把**到这条为止**的记录复制成一条**新会话**并切过去，
原会话一个字都不动——这是「保留这条路，同时试试别的」的非破坏性做法（酒馆的分支也是另存一个聊天文件，
不是在同一份记录里建树）。会话行的 `⋯` 里还有「复制为新会话」，把整条对话复制一份。

**聊天记录互导**：会话行的 `⋯` →「导出为酒馆 jsonl」，导出成酒馆的 JSONL（头部
`chat_metadata` / `user_name` / `character_name`，每条消息 `mes` / `is_user` / `send_date` / `swipes` / `swipe_id`）；
左上「导入记录」把它导进来，**本项目自己的 jsonl 也认**，所以导出再导入是无损往返。
读不懂的行会被跳过并计数，不会整份失败；`greeting` 之外的内容一律以文件为准。

**右侧**：顶部是上下文用量进度条（`已用 / 总量 · 剩余`，>80% 变黄、>100% 变红）。
已用值优先用 provider 实测锚定，构成为估算并带 `~`，标签会写明是哪一种。
提示词栈按四组折叠（系统提示词 / 角色与世界书 /
对话与示例 / 绝对位置注入），每组显示小计；行内开关改动真实生效并记住。
请求预览每行可展开看全文、单独复制、或整份导出 JSON。

**世界书命中**：命中的书在左侧列表上出现「命中 N」徽标，点它直接跳到条目编辑器并高亮
命中的条目与命中的键；空命中时会说明原因（被预算挤掉 / 被时效挡住 / 键不在扫描窗口内）。

**快捷回复**：输入框上方是一条快捷栏，每个按钮是一段常用文本。**点击插入输入框**（还能接着改），
**Ctrl/⌘+点击直接发送**。点右侧「编辑」增删改（每条有按钮文字、正文、是否显示三个字段），
也能**导入酒馆的快捷回复 JSON**（`{ quickReplySlots: [{ mes, label, enabled }] }` 这种形状我们直接吃），
导出也给这个形状。存盘是 `data/quick-replies.json`，纯文本，可以直接手改。

**斜杠命令**：在输入框里打 `/`，上面会跳出命令列表——像 agent CLI 那样，继续打字就按前缀筛，
↑↓ 选，Tab 或 Enter 补全，Esc 收起。按发送键执行，**整行命令不会被当成消息发出去**。
列表**只在输入框内容确实是一条命令行、并且至少匹配到一条命令时才出现**：普通句子里的斜杠
（`价格是 10/20`）、匹配不到的前缀（`/zzz`）、清空之后，都不显示，也不会挡着对话区。目前有：

| 命令 | 作用 |
|---|---|
| `/help` | 列出全部命令（弹窗） |
| `/send <文本>` | 把这段文字当作你的发言发送 |
| `/sys <文本>` | 插一条系统消息，不触发回复 |
| `/regen` | 重新生成最后一条回复 |
| `/continue` | 把最后一条回复接着写下去（不新增消息） |
| `/impersonate` | 替你说一句，以你的身份生成一条消息 |
| `/memory` | 查看、编辑或立即更新长期记忆 |
| `/new [名字]` | 开一个新会话，沿用当前角色 |
| `/model [名字\|默认]` | 查看或切换本会话的模型（`默认` = 清除覆盖） |
| `/persona [名字\|默认]` | 查看或切换本会话的人设（`默认` = 清除覆盖） |
| `/world [书名] [on\|off]` | 查看/挂载/卸载世界书，不给开关就是反转 |
| `/reasoning [on\|off]` | 显示或隐藏思考过程（全局设置） |
| `/export` | 导出当前会话为酒馆 JSONL |
| `/fork` | 把当前会话整份复制成新会话 |

命令全部调用界面本来就能调的接口，没有新增后端路由。`//开头` 仍是普通消息（想发一条带斜杠的话，
写两个斜杠）。

**继续生成 / 替用户发言**：输入框旁有「继续 / 替我说」两个按钮。继续是把最后一条 AI 回复接着写下去
（原地追加，不新增消息，swipe 有多候选时改的是当前那个）；替我说是替你写一条新消息，存成 `user` 消息。
印象提示词是提示词栈里一个真实区块（可开关、有 token 计数），注入位置是**请求的最后一条 user 消息**——
放在对话之前模型会当成续写，而放成 `system` 它又当背景提示、继续替角色说话（两条都是实测过的坑）；文案要求
**照你最近几条的人称与语气来写**，并明确不许替角色说话、不许接着上一条旁白写。设置 → 通用设置里的
「**替我说之后自动让对方回复**」打开后，替我说完会紧接着再跑一轮让对方接话（多一次模型调用，默认关）。
消息菜单里的「继续生成」只在最后一条是 AI 回复时可点，斜杠 `/continue` `/impersonate` 走同一条后端。

**上下文模板**：设置 → 角色扮演里的「上下文模板」，酒馆的 story string
（`{{description}}` / `{{persona}}` / `{{wiBefore}}`…，条件 `{{#if}}`），渲染成提示词栈里
「Context Template」真实区块（scenario 之后，有 token 计数、可单独关）。留空就是原来的栈；
填了之后建议关掉对应的四个独立区块，免得同一段话发两遍。能导入酒馆的 context 预设 JSON，
也能导出回去，「恢复酒馆默认」填它自带的默认模板。模板写错字段或漏了有内容字段时，
装配预览的告警里会明说。

**正则替换**：右侧提示词面板底部「正则…」打开编辑器。每条有名字、表达式、标志、替换、作用域
（只改显示 / 只改提示词 / 两边都改）、开关；替换支持 `$1` / `$&`。存盘永远是原文：
显示侧只改你看到的，提示词侧只改发出去的请求（预览里写明哪条改写了几处），编辑与复制不受影响。
编译不过的存不进去，编辑器里可先「试一条」。

**消息 Markdown**：`**粗体**`、`*斜体*`、`***又粗又斜***`、`~~删除线~~`、`` `代码` ``、围栏代码块、引用、
`#`…`######` 标题、有序/无序列表（含一层缩进嵌套）、`---` 分割线、`[文字](https://…)` 以及**裸 URL** 与
数学公式默认渲染（设置 → 外观可关）。**`---` 一律画成分割线**（不按 CommonMark 当二级标题）；
`![图片](…)` 故意不渲染成 `<img>`——那会把你的 IP 泄露给模型随便编的地址。
`\(…\)` 行内公式与 `\[…\]` / `$$…$$` 公式块（LaTeX 子集：上下标、分数根式、
求和积分、矩阵方程组）直接排出来；朗读时公式会变成词念出来。
消毒是结构性的：只建安全节点，不走 `innerHTML`，卡片里藏的 `<script>` 只会显示成标点。
编辑框与复制用的永远是原文。模型回的 `{{user}}` 这类宏只在阅读时展开（存盘不动）。

**多套人设**：设置 → 角色扮演的人设库可以新增/编辑/删除/应用为默认；
对话头部的「人设：X」按钮只固定本会话的人设（清掉就是跟随默认），
斜杠 `/persona [名字|默认]` 走同一条路。没进库的老会话继续用原来的两栏，
删掉的人设不会弄坏任何会话（自动掉到下一级）。

**图片**：输入框回形针挂图（JPEG/PNG/GIF/WebP，单张 32MB 内），
跟着这条消息发给模型看（`deepseek-flash` 识图已按官方 Vision 指南验证）；
气泡里缩略图，点开放大。原文件存 `data/images/`，消息只记引用；
历史消息只发文字（省 token），预览里写明几张图、约加多少 token。

**翻译**：设了回复语言后，外语消息自动译成它显示（英文开场配中文预设就是这一幕）。
译文默认展示，消息上的「原文/译文」开关随时切回，菜单里的「翻译」可手动重译。
原文永远是存盘的那个，译文是挂在旁边的缓存（编辑、切候选、换语言会重译），
导入导出不带它。每条外语只花一次模型调用，开关在设置 → 通用。

**群聊**：顶栏 `teahouse ▾` →「**新建群聊…**」→ 勾选两个以上角色 → 创建。第一个勾选的当**发起人**
（会话的主角色），勾选顺序就是默认发言顺序；群聊名留空会按成员名自动起。**群聊是会话本身的属性，不是开关**：
成员 ≥2 即为群聊，会话列表里带「群聊 N」徽标、对话头部显示阵容与当前模式。
想改阵容：会话行 `⋯` →「群聊成员…」（勾选即成群，**全取消即回单人**）。

**谁接话由「群聊模式」决定**（右栏，只在群聊里出现）：

| | 模式 | 谁说话 |
| --- | --- | --- |
| **A** | 依次回复（默认） | 导演点一名，其余按阵容顺序补位 |
| **B** | 自然 | `@名字` 优先；其余按**话痨度**掷骰，都没中挑一个话痨的 |
| **C** | 列表 | 阵容顺序，全员依次 |
| **D** | 池化 | 优先"自你上次发言后还没说过话"的人 |
| **E** | 手动 | 只让被 `@` 到的人接话；没点到人就不生成 |

**每轮最多回复**（选人弹窗里设）是所有模式的硬上限：1（默认）/ 2 / 3 / 不限。
`@名字` 开头可以点名（任何模式都优先），重试与重生成沿用原来那个人。
**话痨度**（选人弹窗里每个成员一个滑杆，0–100，羞涩/普通/健谈）存在角色自己身上，
所有群聊共用；卡里若带 `extensions.talkativeness` 会先采纳它，都没有就是 50。

**每个成员可以走自己的接口和模型**（设置 → 模型 →「额外连接」里先存几个端点，再在群聊选人时逐个指定）。
不指定就跟随会话。这样 Enola 可以走 DeepSeek、Haena 走 GLM，文风和啰嗦程度立刻不一样——注意这仍然是
"几次独立调用"，不是多个模型同时在场。选过之后，对话头部的阵容会标出谁走哪条（`Enola（GLM）· Haena`），
轨迹里每轮的 `model` 也记的是发言人实际用的那个。

**一轮几个人回**（选人弹窗里的「每轮回复人数」，默认 1）：一次发言可以让 **2 人 / 3 人 / 全部成员依次**接话。
选多人时，第一名由导演（或轮次）决定，之后每一个都重新走一遍"谁接话"（所以不会同一个人连着说），
每条都是普通回复：各自记 `speaker`、各自进轨迹、各自按自己的连接和模型发。你说一句「你们好」，
三个人就依次开口——不再是只有一个人理你。
每轮模型先点名谁回（答不上来就轮流，永不卡死），输入框 `@名字` 可点名，
重试/重 roll 沿用原发言人。每条回复记着谁说的，头部显示 lineup，轨迹也记。
成员的内嵌世界书全进扫描。

**立绘**：右栏顶上的看板跟着消息自动换表情，手动下拉可钉住一张。
图不用手拷：面板里「管理」→「上传立绘」，选文件、填个关键词就行
（同名会替换；× 删除前会确认）。**PNG 角色卡导入时自动把载体图设为「默认」立绘**，
已有常驻脸不会被覆盖。直接往 `data/sprites/<角色>/` 丢文件也行，
文件名就是关键词（`开心.png` 看到"开心"就上场），`默认.png` 当常驻脸。
当前那张还会虚化铺进聊天区当底图（面板里「聊天底图」开关，默认开，跟手动选择走；
「虚化」滑杆调模糊，「上下」微调取景，智能取景会自己先把脸找出来）。

**语音**：设置里独立成页。消息菜单「朗读」读出来，再点停下；
发新消息也会停掉正在读的。两套引擎：本机（浏览器自带中文语音，
离线免费，默认）与在线（OpenAI 兼容 `/audio/speech`，
Key 只存本机、走服务端代理，浏览器只见音频）。读的是剥掉
Markdown 符号的版本，编辑与原文不受影响。

**外观**：设置里独立成页（通用设置 / 外观 / 模型 / 角色扮演 / 世界书），
主题、配色、Markdown 开关都在这里，右下角小按钮同样能改。

**对话字体**：外观页里六套开源栈（系统默认 / 思源黑体 / 霞鹜文楷 / 思源宋体 /
IBM Plex Sans SC / 等宽）+ 字号；本机有对应字体就用，没有就顺延。
也可以把 `.woff2` 等字体文件丢进 `data/fonts/`（或在外观页上传），自动出现在列表里。
选择存在这台浏览器，不动服务端数据。

**轨迹**：右上角的「轨迹」按钮把右侧面板整体切到轨迹视图（再点一次切回，快捷键 `Ctrl+T`）。它记录的是
**程序做了什么**，与会话记录（说了什么）分开存：`data/chats/<id>.trace.jsonl`，一行一个事件。

- 每一轮请求一行：模型、开始时间、**首 token 延迟**、总时长、provider 报的输入/输出 token、可见长度、
  思考长度、是否被裁剪、这一轮命中了哪些世界书条目、失败原因，以及**这一轮真实发出去的 messages**
  （只保留最近 20 轮；更早的保留数字）。
- 另外还有记忆更新、编辑、删除、从这里重开、分叉、导入、新增候选回复各自的行。
- 顶部每轮一根双色柱（输入 / 输出），点柱子跳到那一轮；下面可按「全部 / 请求 / 世界书 / 记忆 / 改动」筛。
- 选中一行后右边是**概述 / 预览 / 原始内容**三个页签：概述是数字与命中，预览是逐条消息，原始内容是
  可直接复制或导出的请求 JSON。
- 轨迹**只读业务数据**：它不改变模型看到的内容，「清空」也只清轨迹，会话与记忆一条不动。

**检索模式（关键词扫描之上再叠加一条通道）**：关键词扫描永远生效，模式只决定**额外**再注入哪些条目。
右栏「世界书命中」上方有一个下拉，每条会话可以单独选；默认跟随设置里的全局值（没动过时就是「只关键词」）。

- **只关键词**：默认。只有关键词命中的条目进场。
- **全文注入**：把角色的**内嵌书**（技能导入时 references 落成的那本书）整本灌进去，不看关键词。
  内嵌书与世界书撞了同样的正文时，默认让世界书那条生效、丢掉内嵌的那份；设置里打开
  「冲突时强制注入内嵌书」则两份都留。打开「全文注入也含世界书」会连挂载的世界书一起灌（更贵）。
- **向量检索**：见下一节（需要 embedding 端点）。
- **模型点名**：每轮多一次便宜的模型调用，让它从候选目录里点名要哪些条目（上限可配）。
- **agent 按需读文件**：最贴近 Agent Skills 原意的模式。把角色技能包里的文件与卡内嵌书条目列成一张
  清单交给模型，给它一个 `read_file` 工具；它自己决定读哪些，读到的内容作为独立区块注入。
  有上限（默认 3 轮 / 6 个文件，设置页可调），只读本应用自己存下的技能包与内嵌书，**不执行任何东西**。

模式对旧配置兼容：`scan.modelSelect` / `vector.enabled` 这两个老开关在**首次读取**时会映射成对应的模式，
之后由模式接管——设置页里**已经看不到这两个开关**，如果它们还开着而模式不匹配，世界书那页会出现一条
橙色的迁移提示，直接告诉你要把「注入模式」改成哪一项。向量检索现在也只由模式开关控制：档位从
「只关键词」切到「向量检索」才真的发查询。

**向量存储（按语义激活世界书）**：酒馆里靠 embedding 匹配、而不是靠关键词触发的条目，现在这里也能用了。
设置 → 模型里配**两套接口**（都保存着，用「当前使用」切换）：

- **本地**：默认指向 `http://127.0.0.1:11434/v1`（Ollama；LM Studio / llama.cpp / vLLM 同样都提供
  `/v1/embeddings`），不需要 Key，内容不出机器。装法：`ollama pull nomic-embed-text`。
- **远程**：任何 OpenAI 兼容的 embedding 服务（OpenAI / 硅基流动 / 智谱…），要地址、Key、模型。
  **注意**：远程模式会把世界书条目正文与最近几条消息发到那个端点。

配置好之后：条目编辑器里勾上「向量化」（或打开「索引所有条目」）→ 点世界书列表上的「向量 N/M」徽标增量重建
（设置 → 世界书 → 向量检索 里也有「重建全部索引」和状态一览）→ 把「注入模式」切到「向量检索」。之后每一轮会用最近几条
消息查一次，命中的条目**和关键词命中走同一条注入管线**（位置、深度、预算都照旧），右侧命中面板会写
「向量激活 0.42」，分数就是用来调阈值的；那里还有「试一条」可以直接看某句话会命中什么。

你的聊天接口常常**没有** embedding 接口（实测 DeepSeek 的 `/embeddings` 是 404），所以它必须单独配——
设置里的「测试向量服务」会直接告诉你连得上还是连不上。索引存在 `data/worlds/<id>.vectors.json`，
是旁挂文件，**世界书原文一个字都不动**；换 embedding 模型会让旧索引作废并要求重建。

**长期记忆**：设置 → 角色扮演里打开后，每 N 条消息（默认 10，和酒馆的 Memory 扩展同款）让模型把
「上次摘要之后的新消息」接着**上一版摘要**扩写成一段，作为独立区块 `[Summary: …]` 注入到末尾往前
第 2 条的位置。它是提示词栈里一个真实的区块：有独立 token 计数、能在右栏的装配预览里看到实际注入的
内容、也能单独关掉；**聊天记录一条都不会被改写**（摘要只增加内容，从不删消息）。

对话头部的「记忆」徽标（有待更新时会变色）、右栏的「编辑长期记忆…」、以及 `/memory` 都能打开编辑器：
改文本、立即总结、冻结（停止自动更新，手动仍然可用）、清空。摘要存在 `chats/<id>.meta.json`，默认关闭；
导入/导出时会与酒馆 Memory 扩展的 `extra.memory` 双向转换，所以那边的记忆搬过来能接着用。

**外观 / 主题**：右下角有个常驻的小按钮（调色板图标），点开就能换**配色**（靛蓝 / 紫罗兰 / 青碧 / 琥珀 / 玫瑰 / 苔绿）和**明暗**（浅色 / 深色 / 跟随系统）——两秒的事，不用开设置。设置 → 外观页里有同一套选择（同一个组件的两个入口，外加对话字体与字号）。切换只改一个属性，颜色全部来自
一份调色板 token，所以**再加一套主题不用改任何组件**——`web/style.css` 里加一个调色板块、`web/js/themes.js`
里加一条记录（标签、图标、明暗）就完事；`test:web` 会检查每个主题是否把整份契约定义齐了。选择记在浏览器里
（不进 `data/config.json`），「跟随系统」由样式表的 `prefers-color-scheme` 决定，系统切换时立刻跟上。

**配色是第二条正交的轴**：它只覆盖强调色那一族（含你自己的消息气泡），所以 6 配色 × 2 明暗 = 12 种观感，
而加一套配色同样只有几行 CSS——测试也盯着它：三种明暗变体齐全、两块浅色一致、按钮上的色块必须与调色板一致。
配色与明暗都存在浏览器里，随时可换。

**面板折叠**：顶栏右上角两个按钮把左右面板收起，像 IDE 的侧栏一样，中间的对话区自动接管空间。

**服务商预设**：设置 → 模型最上面一行是「服务商预设」下拉，内置 29 条：DeepSeek / 智谱 GLM /
Z.AI（含国内编码端点）/ **OpenCode Zen 与 OpenCode Go** / OpenAI / OpenRouter / Gemini / Anthropic 兼容层 /
Moonshot（国内与国际）/ 通义 / 硅基流动 / Groq / Mistral / xAI / Together / Cerebras / Fireworks /
NVIDIA NIM / Hugging Face Router / Baseten / Vercel AI Gateway / Xiaomi MiMo / Ant Ling /
以及 Ollama、LM Studio、llama.cpp 三个本机端点。选一个就把「接口地址」填好。
**它只填字段，不替你保存**——仍然要点「保存」才生效。表里没有的端点，直接手填地址一样能用。

之所以能这么简单：这些端点现在都讲同一套 **OpenAI Chat Completions** 协议（Gemini 有官方
`/v1beta/openai/`，Anthropic 有官方 OpenAI 兼容层，代价是不支持 caching/extended thinking）。
所以「支持一家新服务商」是**一条数据**，不是一段代码；表里没有的端点直接手填地址也一样能用。

模型 ID / 上下文窗口 / 最大输出也在这张表里（**只登记厂商文档写明的值**，没有就显示「未记录」而不是猜）：
选中已知模型时，那一行会给出「已知 X：窗口 … · 最大输出 …」，点「套用窗口」把值填进「上下文窗口」。

**窗口是模型的事实，不是偏好**：只要当前模型有已知窗口（实测学到的优先于表里的文档值），而「上下文窗口」
还停在出厂默认 65536，服务端就**自动采用**那个已知值——否则新装的环境会一直用 65536 去配一个 100 万的模型，
而且永远不会自愈（离得太远，溢出学习触发不了）。你自己填过的数值（哪怕比默认更小）**一律不动**；
下一次保存会把采用的数值写进 config.json，字段与生效值不会各说各话。

**模型**：配好接口和 Key 后，应用启动时会自动向 `POST /api/models` 拉取一次模型列表。
模型分两层：

- **默认模型**（`config.model`）：在设置 → 模型里选，保存后生效。只有这里会改它。
- **会话模型**（`chats/<id>.meta.json` 的 `model`）：新建会话时**把当时的默认模型快照进来**，
  之后这个会话就用自己的模型；改默认值不会回头改已有会话。顶栏下拉切换的就是这个值，**不会**动默认。
  当它和默认不同时，下拉第一项是「跟随默认（X）」，点它清除覆盖。
- 生成与装配取「会话模型 →（老会话没写时）默认」。

**采样参数**：温度、频率惩罚、存在惩罚、`top_p`，分两层，和模型一个规矩：

- **默认值**（设置 → 模型 → 采样与预算）：新会话建起来时**把当时四个值一起快照进来**，
  之后改默认值不会回头改已有会话。
- **会话值**（右栏「请求参数」）：滑杆 + 数字框，拖动只改数字、松手才保存；
  存的是这个会话自己的快照。「恢复默认」删掉快照，这个会话就跟随实时默认值。
- 分叉出去的会话带着原会话的快照走；`frequency_penalty` / `presence_penalty`
  会真正发给服务商（以前只透了温度/`top_p`/上限）。

两处都是自绘的深色下拉（不是原生 `select`/`datalist`，那两种弹层由浏览器绘制、无法跟随主题），
同一组件渲染，「获取模型列表」按钮/菜单项可随时重拉；连接测试成功时也会复用返回的列表。
**拉取到的列表会缓存到 `localStorage`（`teahouse.models.v1`）**：启动先读缓存，成功拉取再覆盖，
拉取失败（断网）就继续用上一次的列表并标注「离线缓存」，不会变空。
provider 不支持 `/models` 时列表为空，不影响手填。
选择记在浏览器里，下次打开保持。快捷键 `Ctrl+B`（左）/ `Ctrl+Alt+B`（右）。

**回复语言**：设置里可以指定模型用什么语言回答。语言是**自由文本**，所以「中文」「English」
「文言文」都行——想填「火星文」也可以，模型会尽力模仿。留空则不注入任何指令。
指令本身也能改（模板里的 `{{language}}` 会被替换成你填的语言），设置里会**实时显示将要注入的那一行**。

它是一个真正的提示词区块（叫 `Reply Language`，排在 Main Prompt 之后），所以会出现在右侧
提示词栈里、有自己的 token 计数、也能单独关掉——而不是藏在系统提示词里的隐形拼接。

## 设置

左栏是分类（各带一枚内联 SVG 图标），右边一次只显示一页。每一行是「名字 + 说明」在左、控件靠右，
行间一条细分隔线；多行文本（人设、指令模板）整行展开，另外世界书那页按「向量检索 / 扫描范围 / 预算 / 递归 /
背景注入 / 兼容开关」分了组。外观页（主题 + 配色 + 对话字体字号 + Markdown 开关）和右下角的小按钮是同一份实现。

全部字段在 `web/js/settings-schema.js` 里声明一次（页面、图标、分组、控件类型、取值范围、保存载荷）。
几条行为值得记一下：

| 分类 | 管什么 |
|---|---|
| 通用设置 | 回复语言、自定义指令模板、语言预设 + 将要注入那一行的实时预览、外语自动翻译、**「替我说」之后自动让对方回复** |
| 外观 | 主题、配色、对话字体与字号、自投字体、消息 Markdown 开关 |
| 模型 | 接口（**服务商预设** / 地址 / Key / 模型）、**额外连接**（供群聊成员单独选用的端点列表）、**采样与预算**（温度、`top_p`、**频率惩罚**、**存在惩罚**、上下文窗口、回复预留、**单次回复上限 `maxTokens`**、**停止字符串**）、**token 计数**（`tokenizer.json` 路径、**请求真实用量开关**、当前计数模式、连接测试、模型列表拉取）、**思考**（显示思考过程 / 关闭思考） |
| 角色扮演 | 你的名字与你的设定（老两栏，兜底用）、人设库（新增/编辑/删除/应用为默认）、上下文模板（含酒馆预设导入导出） |
| 世界书 | 扫描深度与最小激活、预算百分比与上限、递归、以及 5 个酒馆兼容开关 |

关于其中几个参数：

- **单次回复上限 `maxTokens`**：0 = 不发送该参数、用服务端的默认值。⚠️ 推理模型填小了，思考会把额度吃光、
  **正文返回空字符串**（实测过）；要限也请留足。
- **`top_p`**：核采样，1 = 不裁剪。一般只动温度，两个一起调容易失控。
- **停止字符串**：一行一个（或用逗号分隔），命中即停止生成；用来掐掉模型自问自答、或者模仿出多余的说话人前缀。
- **请求真实用量**：开则请求里带 `stream_options.include_usage`，拿到 provider 的真实 prompt/输出用量——
  预算条的锚定与计数器校准都靠它；关掉就只剩估算。

- 保存是**一次 PUT 提交整份配置**，且所有页的控件一起建，所以改了一半切页不会丢。
- 文本字段**总是会发**（清空「回复语言」因此真的会清空）；数字框被清空时**不发**（不会变成 0）；
  列表字段按数组发（停止字符串不会变成逗号连接的一整条）；API Key 显示 `***` 时不发。
- 取值范围写错时不会默默存下去：会跳到有问题的分类、把原因贴在那一行下面并聚焦。
- 键盘可达：方向键 / `Home` / `End` 换分类，`Tab` 被限制在弹窗内（隐藏页里的控件不会被 Tab 走到），
  `Esc` 关闭。这些都由 `test:ui` 真的按键验证。

## 思考过程（推理模型）

`deepseek-flash` 这类推理模型会先输出一段**思考**（`reasoning_content`）再输出正文。这有两个后果：正文出现前
有一段空白，看起来像卡住；而如果 `maxTokens` 填得太小，思考可能把预算吃光、正文返回空字符串。

两个开关都在设置 → 模型 → 思考：

- **显示思考过程**（默认开）：生成时实时显示「思考中…」，正文开始后变成「思考过程」；这一轮结束后，思考会
  存在这条消息里、默认折叠，可以随时展开回看（按候选回复分别保存，swipe 时看到的是当前那条的思考）。
  它**永远不会**被发回给模型：装配只读正文。
- **关闭思考（实验）**（默认关）：请求里同时发送 `reasoning_effort: "none"` 与 `thinking: {"type":"disabled"}`，
  让模型跳过思考阶段（首字更快）。在 api.deepseek.com 上实测两者都有效；未知参数它只是忽略、不报错，
  但换成会严格校验参数的端点若报错，把这个开关关掉即可。

`test:ui` 用的是 `scripts/shim-dom.ts`：一个手写的极小 DOM（零依赖），只实现 `web/js` 真正用到的那部分。
不引 jsdom 是为了保住「零依赖」；代价是它不通用，所以没实现的 API 直接缺席、一用就报错，而不是悄悄表现得和浏览器不一样。
「设置按钮点了没反应」这类错误在语法检查和 id 检查里都是绿的，只有真的点一下才会暴露——这就是这两套用例存在的理由。
`test:boot` 更进一步：它把 `index.html` 解析进这个 DOM，再用真服务端喂真数据，所以「视图读了一个服务端根本不发的字段」
这种事也会变成一条错误浮层，从而让测试变红。

`test:api` 内置一个假的 OpenAI 兼容服务，所以不需要真实 API Key 也能跑。

测试数据全部由 `npm run fixtures` 生成，**仓库里不含任何第三方内容**。想额外拿真实的
网络世界书验证，把 JSON 丢进 `corpus/local/`（不进版本库），conformance 会自动带上它们；
对真实样本只**报告**未知字段而不判失败，那份报告就是发现新词汇的入口。详见 `corpus/README.md`。

## Token 计数：总量锚定 provider，构成是估算

借 DeepSeek Harness 的做法，**不追求逐模型精确分词**：

- **总量（进度条 / 百分比）锚定真实用量**。每次生成后把服务端返回的
  `usage.prompt_tokens` 存成这个会话的锚点；下次预览的已用值 =
  锚点 + 之后内容的启发式增减量（`projectedTokens`）。所以数字是 provider 实测的，
  又会随着编辑、开关区块立即变化。
- **构成本身是估算**。区块小计、消息逐行、世界书命中都用固定的
  `~4 字符/token` 估算，UI 上一律带 `~`，并且不强行让它加总等于总量
  （中文/JSON 会被这个密度系统性低估）。
- 想精确也可以：把对应模型的 `tokenizer.json`（HuggingFace 格式）放到任意路径，
  在设置里填这个路径，模式会切到 `exact`。这只是可选的覆盖，不是默认流程。

**窗口被谁吃掉了：右栏进度条下面有个可折叠的「构成明细」**（默认收起）。展开后是
一条按通道配色的占比条 + 每个通道一行（提示词栈 / 世界书 / 长期记忆 / agent 读到的文件 /
对话历史 / 图片），行下再列出这个通道里最占地方的条目（世界书命中哪一本哪一条、历史里哪几条
消息最大，超过 12 条折叠成一行「其余 N 条」），最后是「可用于提示词 / 回复预留 / 剩余」。
百分比的分母是**窗口**，与上面的进度条一致；通道没算进去的部分会单独列成「其它／未归类」，
不会悄悄吞掉。锚定/估算与精确/估算的状态从原来那三行说明收成标题行上的一个小标记
（`估算 · 锚定`）。

**上下文窗口会在超了的时候自己学会。** 成功的响应里永远没有窗口大小（只有这次用了多少 token），
但**溢出报错里有**，而且被服务商拒绝的请求不计费。所以：

- 某次生成因为「输入太长」被拒时，服务端从错误原文里认出这是溢出（20+ 家厂商的措辞都认，
  包括 `This model's maximum context length is N tokens`、`prompt is too long: N > M maximum`、
  `Range of input length should be [1, N]`…），抽出窗口数字；
- 顺手把报错里的「你这次实际用了 N tokens」当成一次免费的计数校准（中文被低估的情况很常见）；
- 写进 `data/model-limits.json`（按「端点#模型」缓存），把「上下文窗口」改成能用的值，
  并发一个 `warning` 帧 + toast 告诉你改了什么，然后**自动重试一次**——提示词栈会按新窗口裁历史；
- 之后每个新会话直接用这个缓存值，设置页那张表会把它标成「（实测）」而不是「（文档）」。
- 报错里没有数字（比如 Groq 只说 “Please reduce the length of the messages”）、或者
  服务商根本不报错（z.ai 静默接受、Xiaomi MiMo 截断输入），就只给提示、不猜数字。

## 数据

全部是 `data/` 下的纯文本文件，可以直接看、改、备份：

```
data/config.json
data/characters/<id>/card.png
data/worlds/<id>.json           ← 导入时的原始字节
data/chats/<id>.jsonl           ← 一行一条消息
data/chats/<id>.meta.json       ← 挂载的世界书、宏变量、sticky/cooldown 状态
data/model-limits.json          ← 从服务商那里学到的窗口/输出上限（可删）
```

`sticky`/`cooldown` 这类运行时状态存在会话里，不会污染世界书文件。

## 世界书兼容性

支持并**无损回写**以下来源：

| 来源 | 识别特征 |
|---|---|
| SillyTavern 原生 | `entries` 是以 uid 为键的对象 |
| 独立 CharacterBook | `entries` 是数组，条目用 `keys` / `secondary_keys` / `insertion_order` |
| 角色卡内嵌 | `data.character_book` |
| Agnai Memory Book | `kind === "memory"` |
| Risu Lorebook | `type === "risu"` |
| NovelAI Lorebook | `lorebookVersion` |

其中「独立 CharacterBook」这一类值得单说：**酒馆能导入它但不会正常触发**
（导入只校验 `entries` 存在，而前端按 `entries[uid]` 对象消费、读的是 `entry.key`）。
网上大量流行的世界书（例如 Elden Ring 那套 1221 条的合集）就是这个形态。
在这里它们可以正常使用，也能一键导出成酒馆原生格式。

扫描语义逐条对齐酒馆的 `checkWorldInfo`，包括：正则键 `/pattern/flags`、
整词匹配对多词短语退化为子串、预算按上下文窗口百分比计算、
递归 / 最小激活 / 延迟递归是同一个状态机、包含组的 sticky > 已激活 > override > 评分 > 加权随机。

细节见 [DESIGN.md](DESIGN.md)。
