# Corpus

Two tiers of test data. The distinction is deliberate and load-bearing: the
repository ships nothing that belongs to someone else.

## `owned/` — committed

Generated by `scripts/make-fixtures.ts` (`npm run fixtures`). All content is
original to this project: an invented setting ("the Lantern District"), a PNG
character card assembled from raw IHDR/IDAT/IEND chunks, and a miniature
byte-level BPE tokenizer.

These fixtures gate the build. The conformance suite asserts their format, entry
count, and the exact set of unknown source fields — including fields declared
unknown on purpose, which prove the round trip preserves vocabulary the code does
not understand.

Regenerate with:

```bash
npm run fixtures
```

The generator self-checks every file it writes by parsing it back, so a fixture
that the parser rejects fails immediately instead of confusing a later suite.

## `local/` — git-ignored

Real published world books, if you want to test against them. Drop JSON files
anywhere under this directory and the conformance suite picks them up.

They are treated differently on purpose: **never a build failure**. Their format
and round trip are still asserted, but unknown source fields are *reported*
rather than asserted, because that report is how new vocabulary gets discovered
and then mapped in `src/formats/world-info.ts`.

A useful loop:

1. drop a real book in `corpus/local/`
2. `npm run test:conformance`
3. read the `note: N unrecognised source field(s)` lines
4. add the fields to the field map (or to `KNOWN_SOURCE_KEYS` if they are
   deliberately opaque) and re-run

Nothing in `local/` is ever committed — see `.gitignore`.
